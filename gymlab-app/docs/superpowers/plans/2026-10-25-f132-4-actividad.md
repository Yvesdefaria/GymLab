# 132.4 Actividad Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (native execution: los subagentes están sin permiso en esta sesión). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrar `/logros`, `/objetivos` y `/wearables` al lenguaje Nocturno Minimal conservando datos, funciones y contratos e2e.

**Architecture:** Tres pantallas independientes, una por work unit. Logros: helper puro de filtro + vitrina de 2 columnas + sheet de detalle. Objetivos: cuatro helpers puros de proyección + héroe «próximo hito» + filas hairline + sheet controlado por la página (el picker se abre con el sheet desmontado por z-index). Wearables: estado vacío centrado sin lógica. Sin cambios de esquema, stores ni router.

**Tech Stack:** React 18 + TypeScript + Vite, Tailwind v4 con tokens, react-i18next (es/en), Zustand (`goalStore`), Dexie (sin cambios), Vitest + Testing Library, Playwright Python (`tests/e2e`).

**Spec:** `docs/superpowers/specs/2026-10-24-f132-4-actividad-design.md` (leer completa antes de empezar; es la fuente de verdad de copy, anatomía y estados).

## Global Constraints

- `npm run build` es el typecheck real (`tsc -b`). **Nunca** usar `npx tsc --noEmit` como evidencia.
- `npm test` debe quedar verde; e2e con `python tests/e2e/scripts/with_server.py <test> --port 5245`.
- i18n es/en juntas y tipadas (`EsSchema`); el default del producto es inglés. Nada de literales de UI en componentes.
- Touch targets ≥ 44 px; un solo héroe por pantalla; hairline en vez de tarjetas; sin `panel-light`/`panel-chart`/`panel-hero` como contenedor principal.
- Tokens existentes: `text-gold-bright`, `bg-cta`, `text-success`, `border-border/40`, `kicker`. Sin emojis como icono.
- Contratos e2e que **no** se tocan: `data-achievement` + `aria-label` con metal/estado, `data-progress="general"` y `data-progress="<id>"` con `role`/`aria-*`, `data-tour="logros-medalla"` en la primera tarjeta, contador literal `X/36`, textos `150 kg e1RM`, `112,5 → 150 kg`, `~75 semanas · …`, `+0,5 kg/semana`, `¡Objetivo alcanzado! 150 kg`.
- Stagear rutas exactas; nunca `git add -A` ni `git stash`. Commit **sin push**.
- Review nativo del candidato (diff del workspace) **antes** de cada commit de código. Docs pasivos: readback estructural.
- Sin cambios de router, `vite.config.ts` ni nada nativo → no hace falta emulador.

## Review Focus

1. **Logro con `progress.target === 0`** (p. ej. `guias-completas` sin guías): el tile no renderiza barra ni «0 de 0» y no divide por cero.
2. **Objetivo sin series en los últimos 28 días**: la fila sigue visible y editable, sin fecha inventada; el héroe no declara «todos alcanzados».
3. **Unidades en lb**: héroe, filas y sheet muestran la unidad del usuario y el guardado vuelve a kg.
4. **Colecciones vacías**: 0 desbloqueados, 0 objetivos, 0 proyecciones → estados honestos, sin pantalla en blanco.
5. **Logro reconseguido con variante**: `×N` en el tile y variante visible en el sheet, sin barras duplicadas.

```ts
export type AchievementFilter = 'all' | 'unlocked' | 'locked'

export const filterAchievementsByState = (
  achievements: Achievement[],
  filter: AchievementFilter,
  unlockedIds: string[]
): Achievement[] => {
  if (filter === 'all') return achievements
  const unlocked = new Set(unlockedIds)
  return achievements.filter((a) => (filter === 'unlocked' ? unlocked.has(a.id) : !unlocked.has(a.id)))
}
```
